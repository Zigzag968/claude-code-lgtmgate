# Consumer reference

Every name a consumer can meet, with the remedy. A guard (`node scripts/guards.cjs`, rule `consumer-reference`) fails on a name the code emits that has neither a row here nor an entry in `scripts/consumer-reference-baseline.json`.

- A name is found by a pattern, per family: run reasons are the `reason:` strings of `workflows/deliver-pipeline.js`; assembler refusals are the `<name> at line` messages and `hit('<name>'` calls of `scripts/agent-context.cjs` and its two libraries; configuration keys are the `config.<key>` reads of the engine and of `readConfig` in the assembler; hook messages are the `echo`/`deny` lines of `hooks/*.sh`, named `<script>: <prefix>`.
- Limits: a name built at run time (`secret-${id}`) or carried by a helper object is not found; the pattern for assembler refusals also yields the junk name `at-line`, kept in the baseline as found.
- Reasons the pattern cannot find (probe failures, already-done verdicts, artifact blockers, tick and read reasons) have their rows under Other reasons; the guard does not check that section, so a row there is kept by hand.
- A name leaves the baseline when its row is written here; the baseline never grows.
- Columns: raised at (a file and a symbol, never a line number), what the user sees, remedy. Prerequisites have no pattern: their rows are only checked for a remedy.

## Configuration keys

| name | raised at | what the user sees | remedy |
|---|---|---|---|
| `agentContext` | `readConfig` of `scripts/agent-context.cjs` | `agentContext must be an object`, `agentContext: unknown role "<name>"` or `agentContext.<role>: must be an array of path strings`, and the assembler stops | Set `agentContext` in `.claude/pipeline.config.json` to an object whose keys are `*` or a role (Mia, Sam, Nick, Morgan, Theo) and whose values are arrays of repo paths. |

## Specifics files

- The specifics folder is the `projectSpecifics` path of `.claude/pipeline.config.json`. Its files are `shared.md`, `<role>.md` and `<role>.<lane>.md` (a `<role>.<subject>.md` without a declared lane is plain text of the role), with a lowercase role name: `mia`, `sam`, `nick`, `morgan`, `theo`. Any other name is ignored with the `no-role-match` warning below.
- Only files committed and pushed on the base ref count: the assembler reads `origin/<base>`, never the working tree. A file that is only local is ignored with the `not-on-base-ref` warning below.
- A file listed in `agentContext` is a context file. It takes no frontmatter, no line starting with `@` outside a closed fenced code block, no comment opener (`<!--`) left unclosed or carrying an engine marker, and no zero-width or control character.
- `agentContext["*"]` files follow `shared.md` and are sent once, inside the shared block, never copied into a role text. Over 2048 bytes together is a warning in `warnings[]` (`shared-oversize`), exit code unchanged. A `*` path that is a file of the specifics folder stays with its role. A role whose only source was a `*` file has no block of its own.
- At most 8 files per source: the role's files in the folder, and each `agentContext` list.

## Assembler refusals named at run time

The assembler builds these names while it runs (from a variable, or in a message without `at line`), so the guard does not extract them and does not check these rows. `<path>: <rule> at line 0` for the path and file rules; the config rules print the message shown.

| name | raised at | what the user sees | remedy |
|---|---|---|---|
| `invalid-path` | `validatePath` of `scripts/agent-context.cjs` | `<path>: invalid-path at line 0` (or `projectSpecifics: invalid-path`): the path holds a character outside letters, digits and `. _ / -` | Rename the file or folder to those characters only. |
| `absolute-path` | `validatePath` of `scripts/agent-context.cjs` | `<path>: absolute-path at line 0`: the path starts with `/` | Write the path relative to the repository root. |
| `bad-segment` | `validatePath` of `scripts/agent-context.cjs` | `<path>: bad-segment at line 0`: the path has an empty, `.` or `..` segment | Write the path without those segments, such as `docs/rules.md`. |
| `not-md` | `validatePath` of `scripts/agent-context.cjs` | `<path>: not-md at line 0`: a file listed in `agentContext` does not end in `.md` | List a `.md` file, or rename the file. |
| `symlink` | `entryProblem` of `scripts/agent-context.cjs` | `<path>: symlink at line 0`: the file is a symbolic link in the commit tree | Commit a regular file in its place. |
| `submodule` | `entryProblem` of `scripts/agent-context.cjs` | `<path>: submodule at line 0`: the path is a submodule | Commit a regular `.md` file in its place. |
| `tree` | `entryProblem` of `scripts/agent-context.cjs` | `<path>: tree at line 0`: the path is a folder | List the `.md` files of the folder one by one. |
| `not-regular-file` | `entryProblem` of `scripts/agent-context.cjs` | `<path>: not-regular-file at line 0`: the entry is neither a regular file, a link, a submodule nor a folder | Commit a regular `.md` file in its place. |
| `ceiling` | `assemble` of `scripts/agent-context.cjs` | `ceiling: <n> bytes of specifics exceed 65536 at line 0` and exit 4: the raw files together are over 65536 bytes | Shorten the files or drop some from `agentContext`; a role text above 6144 bytes only warns. |
| `secret-*` | `checkContent` of `scripts/lib/agent-context-text.cjs` | `<path>: secret-<kind> at line N`: the text matches a token or private-key form (`<kind>` is `github-token`, `github-pat`, `sk-rk-key` or `pem-private-key`); the value is never printed | Remove the secret from the file and rotate it. |
| `bad ref` | `resolveReference` of `scripts/agent-context.cjs` | `bad ref: <ref> ...` and exit 2: `--ref` is not `origin/<branch>` or does not resolve to a commit | Pass `--ref origin/<branch>` for a branch fetched from origin. |
| `unknown role` | `readConfig` of `scripts/agent-context.cjs` | `agentContext: unknown role "<name>"` (or `unknown role: <name>` after `--print` or `--accept-oversize`) and exit 2 | Use `*` or one of Mia, Sam, Nick, Morgan, Theo, spelt that way. |

## Assembler warnings

The assembler prints these on stderr as `agent-context: warning: <path>: <rule>. <remedy>`, once per file and rule, and repeats each in the `warnings` array of its JSON. The exit code stays 0 and no digest changes. The guard reads these names from `WARNING_REMEDY` in `scripts/lib/agent-context-lanes.cjs` and checks these rows against them.

| name | raised at | what the user sees | remedy |
|---|---|---|---|
| `not-on-base-ref` | `folderWarnings` of `scripts/lib/agent-context-lanes.cjs` | A file of the specifics folder is in the working tree but not on the base ref (untracked, or committed and not pushed): no role receives it | Commit the file and merge it into the base branch. |
| `no-role-match` | `folderWarnings` of `scripts/lib/agent-context-lanes.cjs` | A file of the specifics folder on the base ref matches no `<role>.md`, `<role>.<lane>.md` or `shared.md` (a capital letter, another extension, a name that is not a role): it is ignored | Rename it after a role in lowercase, or list it in `agentContext`. |
| `frontmatter-on-shared-file` | `assemble` of `scripts/agent-context.cjs` | `shared.md` opens with a frontmatter block: its keys are discarded | Remove the frontmatter from `shared.md`. |
| `lane-captured-from-other-role` | `classifyLanes` of `scripts/lib/agent-context-lanes.cjs` | A file without frontmatter, such as `nick.ios.md`, joins the `ios` lane that only another role (`sam.ios.md`) declares | Give the file its own `lane:` frontmatter, or rename it so its second segment is not that lane. |
| `empty-ignored` | `assemble` of `scripts/agent-context.cjs` | A file holds only comments or blank lines once its frontmatter is removed: it adds nothing | Write the rules in it or delete it. |
